# Chimera 测试编写与验收规范

本规范用于让测试在产品发生回归时可靠地失败，并留下足以定位问题的证据。适用于本项目新增、修改和审查测试的工作，重点约束 `tauri-e2e/`。纯逻辑、Rust 事务和测试框架辅助函数，应优先在更小的测试边界验证。

**MUST（必须）和 MUST NOT（禁止）是项目审查要求；SHOULD（应当）允许有依据的偏离。** 本文件已经通过根目录 [AGENTS.md](../../AGENTS.md) 接入开发指引；这不代表所有规则已有自动检查。既有用例也不因此自动合规。新增或修改的测试应满足适用条款；未修改的历史缺口按文末清单逐步处理。

依据核对日期：2026-09-13。“上游”专指 WebdriverIO、Tauri service、Rust WebDriver 插件、Mocha 等测试依赖。版本、源码定位和工具限制见[上游依据](upstream-evidence.md)。用例设计和交付记录使用[测试契约模板](test-contract-template.md)。

## 1. 先定义测试能证明什么

### T01：每个用例必须有可证伪的契约

- MUST 写清楚：初始状态、一次被测操作、预期结果、结果的独立来源，以及哪种错误实现会让测试失败。可以放在 spec 的头部注释；复杂场景另建契约文档。
- MUST 使用行为标题，例如“切换模式后内核和当前页面同步更新”；仅写“工作正常”“调用不报错”不构成契约。
- MUST 区分准备、操作、观察、清理。观察结果的代码不得重做被测业务逻辑来计算同一个答案，也不得修改状态来促成通过。
- MUST 根据风险选择失败路径。涉及落盘、配置激活、转换、下载、重启的改动，至少覆盖一个相关失败或取消路径及旧状态不变量；仅布局改动不强制增加网络或恢复测试。
- SHOULD 为修复回归的测试提供“旧实现因目标断言失败、新实现通过”的证据。旧版本不可运行时，记录原因，并通过临时故障注入或等价反例验证断言；不得用编译失败、启动失败代替目标回归证据。

### T02：测试名称和报告不得超出实际边界

| 边界          | 实际经过的部分                     | 可以证明                     | 不能单独证明                |
| ------------- | ---------------------------------- | ---------------------------- | --------------------------- |
| 单元          | 纯函数、模型或隔离模块             | 解析、排序、状态转换等规则   | IPC、真实桌面、网络可用     |
| 集成          | 多个真实模块，可从 IPC/API 触发    | 命令到事务、文件、内核的连接 | 对应 UI 入口可用            |
| 桌面 UI E2E   | 测试程序中的 UI → IPC → 后端       | 声明的用户流程与状态同步     | 未执行的系统级交互          |
| 网络 E2E      | 上述操作 → 真实代理请求 → 可控目标 | 指定路径实际收发数据         | 其他协议、DNS、TUN 自动正确 |
| 发行/系统验证 | 实际安装产物、进程和系统设置       | 被执行的平台集成行为         | 其他平台也通过              |

MUST 根据实际触发方式记录边界；文件名为 `.e2e.ts` 不改变它。IPC 可以用于准备数据、清理和只读观察；若核心操作直接调用 IPC，则必须标注为集成边界，不能声称对应 UI 流程已覆盖。模拟被测 IPC/内核响应的用例只能证明模拟边界以内的行为。[Tauri 测试边界说明](https://v2.tauri.app/develop/tests/)

## 2. 交互和观察必须保留发现问题的能力

### T03：不能用绕过交互的手段修好测试

- MUST 优先使用 WebdriverIO 的元素和键盘接口。MUST 核对目标窗口、当前路由、唯一选择器及操作前状态；不能把打开窗口的命令成功视为已切换窗口。
- MUST NOT 在被测操作中直接修改 React 状态、DOM 属性、缓存、配置文件或调用目标 IPC，代替原本需要验证的点击、输入、保存。
- MUST NOT 在点击失败后自动换成 DOM `click()`、直接导航或 IPC，仍然报告原交互通过。驱动限制必须有最小复现、锁定版本依据及明确的覆盖降级。
- 当前 embedded 插件的元素点击使用脚本，桌面 pointer 路径合成 MouseEvent。**即使调用 `element.click()`，也不能据此声称验证了原生鼠标、完整 PointerEvent 序列或可信事件。** 依赖这些行为的契约必须使用已验证支持的驱动/系统测试，或如实记为未覆盖，见 [U04](upstream-evidence.md#u04-rust-插件的点击与会话边界)。
- 键盘激活可以用于键盘或菜单布局契约；不能替代“鼠标可打开菜单”的验收。通过脚本设置焦点后测试 Enter，也不能声称验证了 Tab 焦点顺序。

### T04：选择器和界面断言要对应产品契约

- MUST 优先使用唯一的稳定 ID、已有 `data-slot` 加业务 UID，或在当前驱动已验证支持的可访问名称。文案定位必须固定语言，避免跨语言正则命中错误元素。
- MUST NOT 用数组首项、宽泛 `li` 文本匹配或布局层级定位关键业务操作，除非顺序/层级本身就是被测契约，并先断言集合身份和数量。
- 动态 DOM 结果 MUST 使用可重试的 WDIO 元素断言，或显式等待后再用 Node `assert` 检查快照。Node `assert` 自身不会自动等待。不要把两种 `expect`/`assert` 混为一谈。
- 布局测试 MUST 固定窗口、实际视口、语言、主题、字体加载状态和动画完成条件；尺寸容差必须有设计或缩放依据，不能为了通过任意放宽。
- 功能测试 SHOULD 断言可见状态、可用操作和业务结果；CSS 类名及像素值只用于明确的样式契约。保存截图属于证据采集，未实现基线比较就不能称为视觉差异测试。

选择器和等待式断言的工具依据：[WDIO Best Practices](https://webdriver.io/docs/bestpractices/)。本项目对业务身份和布局条件的要求是本地审查规则。

### T05：等待只能观察，不能制造成功

- MUST 将业务操作放在轮询外，轮询内只读状态。MUST NOT 在 `waitUntil` 中重复点击、保存、激活、下载、刷新或重启。
- MUST 等待具体结果，例如目标配置 UID 已激活且内核加载了目标值。`document.readyState`、根节点非空、按钮出现，只能说明对应阶段就绪。
- MUST NOT 用固定 `browser.pause()` / sleep 代替业务完成条件。网络关闭后的稳定观察窗口可以使用定时采样，但必须有起止条件、期限和每次断言；它不是“睡一会儿再赌状态”。
- MUST 为轮询以及内部 HTTP/子进程操作设置有界期限。外层 `waitUntil` 超时不等于底层 `fetch` 被取消；HTTP 应使用 `AbortSignal.timeout()` 等实际取消机制。
- MUST 保留最终观察值和错误原因。``timeoutMsg: `...${lastState}` `` 在调用时生成，不会随轮询更新；应在等待失败的 catch 中读取最新诊断并保留原始 cause。
- MUST NOT 把任意异常变成 `false` 或默认成功值。仅已声明的暂态错误可继续等待，同时记录最后错误；永久错误必须按失败处理，不能假定轮询回调抛错总会立即终止 WDIO 的计时器。

工具依据：[waitUntil 文档](https://webdriver.io/docs/api/browser/waitUntil/)及 [U02 源码](upstream-evidence.md#u02-webdriverio-等待与重建会话)。

### T06：先验证当前状态同步，再验证刷新和重启

- 设置变更 MUST 先在**不刷新页面**的情况下验证当前 UI 与权威状态收敛。MUST NOT 用“内核已更新、UI 没更新就刷新”的逻辑掩盖事件同步回归。
- 若契约涉及页面重载，必须在首次同步验证完成后独立执行刷新，再验证结果。
- 若契约涉及持久化到磁盘，MUST 读取相应持久化产物或以真正的应用冷启动验证；IPC 从内存返回的值不能单独证明落盘成功。
- 若声称“退出重开后保留”，MUST 确认旧应用及相关内核进程结束，使用同一专属测试目录启动新进程，记录进程身份/启动时间，并重新验证结果。新 WebDriver session ID 不足以证明冷启动。
- 运行配置生命周期 MUST 验证本次操作的具体标记或目标字段、激活身份和内核状态；文件存在、通用文件头、`Running` 不能单独证明加载的是本次产物。

`reloadSession()` 和 Rust 插件会话删除的实际边界见 [U02](upstream-evidence.md#u02-webdriverio-等待与重建会话) 与 [U04](upstream-evidence.md#u04-rust-插件的点击与会话边界)。

## 3. 状态、网络和失败必须可控

### T07：每个测试拥有自己的资源

- MUST 使用框架创建的测试 config/data 目录，业务资源使用本次运行可追溯的唯一 ID。不得读取用户真实订阅、复用用户配置目录或删除其他用例的数据。
- MUST 明确进程、端口、profile、窗口、localStorage、mock 和探测服务器的所有者。**当前目录按整轮运行隔离，不是每个 spec/it 独立；`maxInstances: 1` 也不消除状态污染。**
- MUST 使单个用例可独立准备和验证，不依赖前一个 `it` 成功后的状态。复杂连续操作应放在同一个生命周期用例中，并保持辅助函数职责清楚。
- MUST 从真实初始状态确定变更方向；若测试要求初始配置为空，先验证该前提，不能删除不属于自己的配置来满足它。
- MUST NOT 并行执行共享窗口的输入/点击或共享运行配置的写操作。只有互不影响的只读观察或隔离资源操作才可并发。
- 新增并行运行前 MUST 证明配置目录、驱动与内核端口、进程回收和系统代理不冲突。当前清理按二进制目录筛选进程，不能直接宣称支持同目录多轮并发。

### T08：负向测试必须排除“环境坏了所以失败”

- 网络用例 MUST 使用可控服务器和本次请求唯一 token，并验证目标服务收到的请求或代理路径证据。不能仅检查端口开放或 HTTP 状态码。
- “关闭后不能连接”必须先证明同一客户端、目标和代理路径在开启时可用；关闭后持续验证规定窗口，并验证目标服务器仍健康。目标服务停机、curl 不存在、SSH 失败不能算访问被成功阻止。
- MUST 控制并记录 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY` 及大小写形式对探测的影响；正向样本必须证明走了预期代理，不能被直连绕过。只报告相关变量的脱敏值。
- hermetic 用例 MUST 使用本地或随测试启动的依赖服务，不依赖公网可达、真实订阅或 WSL/LAN 客户端。下载构建资源属于准备阶段，不能据此声称整个 CI 完全离线。
- MUST 对外部前置条件做显式检查。明确选择 `network` 而缺少所需环境时应失败并说明原因；平台不适用的跳过必须在报告中列明，不能报告该覆盖已通过。

### T09：失败路径必须验证旧状态和用户反馈

涉及配置、转换、更新或重启失败时，MUST 按本次产品契约选择并断言：错误反馈、旧激活配置、旧运行字段、已落盘内容、候选文件和已有连接等不变量。不得默认所有失败都应停核，也不得默认所有失败都能无损恢复。

MUST 将失败注入到所声明的真实边界。例如本地订阅服务器返回非法 YAML 能验证下载后的校验链路；模拟 IPC 直接报错只能验证 UI 对该错误的处理。二者不能互相替代。

取消/校验失败后，MUST 等待表单明确进入取消或错误状态，再比较持久化集合/计数。提交后立即断言“没有卡片”可能在异步任务开始前就通过；应增加对应后端/文件观察或刷新后的独立检查。

### T10：清理要完整，也不能覆盖原始失败

- MUST 在创建资源后立即登记清理责任；准备阶段部分失败也必须清理已经创建的资源。测试主体放在 `try` 内，不能把会留下副作用的创建步骤全放在保护范围外。
- MUST 按依赖顺序恢复原配置、关闭本测试服务器/窗口、回收本测试子进程、恢复宿主设置。每一步清理失败后仍要尝试其他必要步骤。
- MUST 同时保留测试失败和清理失败，例如收集错误后抛出 `AggregateError`；MUST NOT 在清理中无记录 `.catch(() => undefined)`，也不能由 finally 的新错误覆盖原始失败。
- MUST 在破坏现场的清理前采集失败证据。会话有效时读取 UI；会话已失效时使用磁盘日志、退出状态和进程信息，不再反复执行 WebDriver 命令。
- MUST 校验清理对象的归属，禁止按进程名全局杀进程、删除整个共享临时根目录或强制覆盖用户配置。宿主代理恢复必须可核验；当前框架仅提供 Windows 专用兜底，不代表其他平台同样已实现。
- 框架 `after` / `afterSession` / `onComplete` 的职责与进程上下文不同，MUST 遵照 [U03](upstream-evidence.md#u03-tauri-service-启动恢复和清理) 安排操作。系统强制终止时 hooks 不保证执行，应依赖专属资源识别与后续回收。

## 4. 用例最小验收矩阵

只要求覆盖本次改动涉及的行；不要为低影响变更机械新增昂贵 E2E。

| 改动类型           | 成功侧至少验证                                         | 相关失败/边界侧至少验证                  | 不充分的证据                 |
| ------------------ | ------------------------------------------------------ | ---------------------------------------- | ---------------------------- |
| 运行设置           | 操作前后 UI、内核实际字段；声明持久化时追加磁盘/冷启动 | 写入失败后的提示及约定旧状态             | 开关 checked、IPC 无异常     |
| 配置创建/激活/排序 | 本次 UID、顺序语义、运行产物目标字段、内核实际值       | 取消/非法输入/重建失败后的不变量         | 卡片数量、任意运行文件存在   |
| JS/Lua/合并转换    | 用唯一输入验证转换效果、顺序和作用域                   | 本次相关的脚本失败/超时/非法输出         | 只调用转换命令或读取诊断对象 |
| 订阅导入/更新      | 可控服务器请求、内容版本、持久化与激活结果             | 相关的错误响应/非法内容/中断及旧配置     | 空 URL 校验代表整个下载流程  |
| 代理模式/LAN/TUN   | 指定客户端经指定路径获取 token；系统状态按契约核对     | 基线健康条件下的阻断或恢复               | 内核显示 Running、端口在监听 |
| 存储/事件同步      | 外部变更后当前已挂载页面自行同步                       | 重复事件或无关事件不破坏状态，按改动选择 | 手动 refresh 后值正确        |
| 菜单/布局/图标     | 声明的交互、稳定视口下实际几何/可见内容                | 键盘关闭、加载失败等相关边界             | CSS 类存在、单张截图         |
| 内核管理           | 实际切换身份、就绪和必要代理请求                       | 启动失败与旧状态恢复契约                 | 内核卡片渲染                 |
| 单实例/自启动/安装 | 对应正式构建与系统行为                                 | 重复启动/禁用/升级失败等相关边界         | 当前 e2e 特性构建通过        |

## 5. 异步、重试与诊断

### T11：异步完成必须归测试框架管理

- MUST `await` 或返回所有断言、命令、清理 Promise；禁止 `forEach(async ...)` 和未收集的后台 Promise。
- Mocha 用例 MUST 统一使用 async/await；不得在同一用例同时使用 Promise 和 `done`。不要使用 async `describe` 准备资源，异步准备应进入 hooks。[Mocha 异步约定](https://mochajs.org/features/asynchronous-code/)、[Hooks](https://mochajs.org/features/hooks/)
- 当前 Mocha 用例/hook 超时为 120 秒，驱动单次请求超时也是 120 秒，业务等待通常更短。MUST 审核总预算，为诊断与清理留出时间；不能假定增加外层超时会取消内部操作。
- MUST NOT 用增加全局超时、套件重试或忽略错误作为修复的唯一证据。变更预算需说明慢在哪里、预期上限和测量依据。

### T12：重试通过不能抹去第一次失败

MUST 区分 WebDriver 请求重试、Mocha 用例重试和 WDIO spec 重试；当前 `connectionRetryCount: 1` 是请求层设置，不等于失败用例重跑一次。[WDIO 配置](https://webdriver.io/docs/configuration/#connectionretrycount)、[重试说明](https://webdriver.io/docs/retry/)

新用例 SHOULD 默认不增加测试级重试。为调查偶发问题重复运行时，MUST 保留每次结果及失败证据，统计首次通过和重试通过。套件中发生非预期应用退出或 service 自动拉起，必须列为异常事件调查；后续用例通过不能证明没有崩溃。[U03](upstream-evidence.md#u03-tauri-service-启动恢复和清理)

`.only` 禁止进入交付。新增 `.skip`、`this.skip()` 或临时绕过必须记录适用平台、原因、责任人/任务、未覆盖行为和解除条件；已选择且适用的关键测试因准备失败而跳过，不得记为验收成功。

### T13：失败必须留下可用证据

失败记录 MUST 包含用例/规则 ID、失败阶段、期望与最后实际值、原始错误、平台与驱动版本、应用构建身份及内核身份。按失败边界采集：

- 会话存活：窗口/路由/视口、截图、目标元素状态和相关前端错误。
- 后端/内核：本次测试日志、退出状态、脱敏后的目标配置字段/产物标记。
- 网络：客户端、目标、代理地址、监听状态、token 和服务请求记录；命令 stdout/stderr 脱敏。
- 清理：已恢复项、失败项、仍存活的本测试资源。

MUST 为证据使用运行 ID + spec + 用例 + 尝试次数的唯一路径，存放在不会随 runtime 目录删除的位置。诊断读取也必须有期限；截图失败要记录，但不能覆盖业务失败。

MUST NOT 保存真实订阅凭据、完整认证头或不相关宿主环境信息。当前 harness 在设置 `CHIMERA_E2E_ARTIFACT_DIR` 时会通过 `afterTest` 采集失败截图、页面源码和错误文本，CI 会上传该目录；这些产物仍可能包含应用内容，必须使用合成数据并在分享前复核。未启用该目录的本地运行，需要按本节提供等价留证，不能因为 CI 有统一 hook 就假定本地失败可诊断。

## 6. 套件与交付门槛

### T14：运行范围必须与改动范围相符

每个新 spec MUST 恰好归属一个 `baseE2eSuites` 分组；组合套件由其派生，运行 `spec-suites.test.ts` 验证遗漏/重复。`critical`、`hermetic` 和 `all` 的含义以[实际定义](../../tauri-e2e/spec-suites.ts)为准。

当前 CI 行为见[工作流](../../.github/workflows/e2e.yaml)：匹配路径和分支的 PR 跑 critical，push 跑 smoke，每日跑 hermetic；均在 Windows。工作流还会运行 `controller-fallback` 回归并上传 E2E 诊断；network 和 upgrade 不在这些自动选择中，仍需要额外环境/专用 runner。根目录 `e2e:tauri:test` 和包内 `test` 默认只跑 smoke。

下列是审查所需证据，**不表示工作流已经自动执行所有项目**：

| 本次改动                                  | 必须运行/提供                                                     |
| ----------------------------------------- | ----------------------------------------------------------------- |
| 纯测试文档                                | 格式、内部链接、命令与现有脚本一致性检查；无需桌面构建            |
| 某个 spec                                 | E2E typecheck、套件登记检查、目标 spec 和所属基础套件             |
| 公共 helper / wdio 配置 / 依赖 / 清理逻辑 | 框架单元测试、typecheck、受影响套件；影响全局行为时运行 hermetic  |
| 产品业务回归                              | 最小相关单元/集成检查及覆盖该行为的 E2E；修改前后或等价反例证据   |
| 网络/系统行为                             | 对应专属环境结果；托管 CI 不支持时明确尚未验证，不能用 smoke 代替 |

若基础套件为 settings/main 而 PR 自动只跑 critical，MUST 额外运行受影响套件并附结果。新覆盖若应成为 PR 必检，必须同步调整组合套件或 CI；把文件放进目录不代表 PR 会运行它。

框架、状态隔离或偶发失败修复，还应验证目标独立运行及同一进程环境下与其他相关用例组合运行。仅在这些风险存在时增加重复/顺序扰动验证，不要求每次低影响变更全量重跑。

从仓库根目录运行，先满足 Node 24 和 packageManager 指定的 pnpm 版本：

当前 `test:unit` 是显式文件列表：`agent-issue-guidance.test.ts`、`process-cleanup.test.ts`、`privacy-safe-context.test.ts`、`runtime-path.test.ts` 和 `spec-suites.test.ts`。新增 harness 单元测试必须同步加入该命令，否则文件存在不代表会执行。

```bash
pnpm install --frozen-lockfile
pnpm --filter @chimera/tauri-e2e test:unit
pnpm --filter @chimera/tauri-e2e typecheck
# 需要新建或更新桌面测试产物时执行；check 会准备/下载 sidecar 和资源。
pnpm check
pnpm e2e:tauri:build
# 把示例路径替换为本次目标；此命令不会自动重新构建应用。
pnpm --filter @chimera/tauri-e2e exec wdio run ./wdio.conf.ts --spec ./specs/ipv6-runtime-setting.e2e.ts
pnpm --filter @chimera/tauri-e2e test:runtime
```

MUST 记录测试二进制的路径、构建来源和时间/哈希，确保对应本次产品代码。若使用 `CHIMERA_E2E_BINARY` 覆盖路径，也必须验证对应的 e2e 特性和前端产物。不要拿旧二进制通过当作当前代码通过。工具或平台缺失时如实记录未运行及原因；静态检查通过不得写成桌面测试通过。
