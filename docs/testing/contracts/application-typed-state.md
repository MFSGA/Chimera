# Typed application state through the legacy IPC surface

- **Contract ID:** `application-typed-state`.
- **Boundary:** Desktop integration E2E through the real Tauri WebView, IPC, typed application settings owner, legacy `get_verge_config` compatibility API, and isolated `application.yaml`. The changed setting is prepared by test-only IPC; this does not verify a user-facing setting control.
- **Suite and execution:** `application-typed-state.e2e.ts`, registered in `settings` by `tauri-e2e/spec-suites.ts` and included in the Windows `hermetic` PR suite.
- **Initial state:** The dedicated E2E runtime's current `enable_auto_check_update` value is read through legacy `get_verge_config`; the raw typed `application.yaml` is available through `CHIMERA_E2E_RUNTIME_DIR`.
- **Operation:** Invert the setting once through `patch_verge_config`. The test waits for the legacy read API to observe the changed value and for the exact typed YAML field to persist. It then refreshes the main WebView.
- **Independent result:** The legacy API observes the value written through the shared typed owner, and the isolated `application.yaml` contains the same boolean. After refresh, the legacy read API and disk still report the changed value.
- **Navigation/render stages:** The vendored WebDriver refresh implementation starts `window.location.reload()` and returns before the next document load completes. After refresh, the test waits up to 30 seconds for `document.readyState === "complete"`, then separately waits up to 60 seconds for the React root to mount. In PR #507 run `39429486331`, the first post-refresh observation reached `readyState: complete` with an empty root within one second; the 30-second root wait then expired, while the failure screenshot showed the Dashboard rendered. The longer mount budget covers that observed boundary without removing the render assertion. The test's Mocha limit is 180 seconds to leave bounded time for cleanup.
- **Failure sensitivity:** A broken legacy-to-typed mapping, missing disk write, or page reload that leaves the WebView blank fails the corresponding assertion. The test distinguishes document navigation from React rendering so a slow navigation response is not mistaken for a product render failure.
- **Cleanup and diagnostics:** Restore the original setting through the same shared API and verify both API and YAML. Before cleanup, write redacted state observations, app identity, screenshot and page source to the isolated E2E artifact directory; aggregate cleanup errors with the test failure.
- **Limits:** This does not exercise a UI toggle, process restart/cold-start persistence, Service/TUN, system proxy, or network behavior. A WebView refresh is not a cold application restart.
- **Rollback:** Revert the spec helper and this contract; no production behavior or persistent user data migration is changed.
