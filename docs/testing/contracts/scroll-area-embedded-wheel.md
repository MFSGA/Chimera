- **Initial state:** In the isolated desktop test session, open Main `/main/settings/chimera` with a 1240 × 638 window. Verify six settings groups, a real nested scroll viewport, more than 120px of scroll range, `scrollTop=0` and expanded title visible.
- **Action:** Use a WebDriver `wheel.scroll` action with explicit viewport coordinates whose hit target lies inside the Settings `scroll-area-viewport`. First install a once-only capture-phase `wheel` handler that records receipt and calls `preventDefault`; assert the event was received, `defaultPrevented=true`, and `scrollTop=0` (a wheel that never arrived must not falsely pass). Then repeat the same wheel action without cancellation, and finally perform wheel-up.
- **Independent observations:** Read nested viewport `scrollTop`, ScrollArea `data-top` and `data-scroll-direction`, and both Settings title `data-show-title` flags. Wheel-down must scroll >40px, report `down` and reveal compact title; wheel-up must restore top, `up` and expanded title. Window scroll alone, no scroll, a missing viewport, a canceled action that still scrolls, or a sticky header that never transitions all fail.
- **Behavior boundary:** The vendored driver dispatches a JavaScript-created `WheelEvent` (`isTrusted=false`) and must emulate its uncanceled default scrolling on the nearest scrollable ancestor. A passing test demonstrates this embedded WebDriver path and the product's response to real scroll changes in the nested element. It **does not** prove trusted OS mouse wheel input, touchpad behavior, native overscroll physics, or accessibility.
