## Baseline, objective and scope

- Local target: Chimera `master`, starting from `ddad1aac71c36b01aac10f650abbf3cc8749b39e`, with the earlier UI alignment working tree intentionally preserved.

The three missing UI files and their relevant existing UI dependencies were checked for identical blob content across these reference revisions in the preceding audit. This slice does not advance the pinned ref.
- Objective: port the remaining `sidebar.tsx`, `date-time-field.tsx`, and `shared-tooltip.tsx` at identical relative paths, along with their actual upstream support dependencies.
- Non-goals: replace legacy UI or already deployed app routing, rewire main UI's existing mobile hook, change backend/IPC/agent, change user data, or remove Chimera-specific visual exports.
- Risk: L2 for frontend dependencies and resolution configuration; L1 for source-only packages/presentational components. No intentional system or persisted-data side effects. Browser interaction/desktop E2E and cross-platform CI are still required before a merge decision.

### Deviations and compatibility

- This finishes **same-relative-path coverage** for the ref UI TSX files; it is **not** full behavioral/visual parity. Existing `tooltip.tsx`, `dropdown-menu.tsx`, `text-marquee.tsx`, `scroll-area.tsx`, `dnd-grid`, `slider.tsx`, `sparkline.tsx`, and other common paths still need file-by-file ref semantic comparison.
- The shared `@chimera/hooks` implementation is copied accurately, but the pre-existing `@chimera/ui` root hook and the Chimera main-app `use-is-moblie.tsx` hook remain for compatibility until their consumers are migrated and browser breakpoints are tested. This temporarily means two responsive hook implementations with the same breakpoint thresholds, not two shared application-state owners.
- The reference tooltip controls opening delays through an app-level provider, whereas Chimera's existing Tooltip root supplies a local zero-delay provider. Replacing the root now would change many current app controls without interaction evidence. Adding `TooltipBubble` is the smallest safe compatibility boundary for the new `SharedTooltip`.
- UI's Radix `1.8.1` and app's direct Radix `1.6.7` can coexist but mixed-version nested overlays must be exercised in real browser tests before standardizing the app dependency. No automatic version bump was applied across the app.
- The component code retains the reference `radix-ui/internal` import, now available through the `1.8.1` package wildcard export. Future upstream Radix changes could invalidate that internal API; track during dependency updates.

## Follow-up audit of existing UI paths

- `frontend/ui/src/separator.tsx`: reference and Chimera have the same element composition and style rules after brand and formatter normalization; no behavior migration required.
- `frontend/ui/src/highlight-text.tsx`: Chimera accepts legacy `search`/`text` as well as the ref `searchText`/`children` shape, while the highlighting algorithm remains the same. Keep those extra props until app call sites have been updated.
- `frontend/ui/src/text-marquee.tsx`: ref measures visible text on change, animates with the browser Web Animations API, uses an absolutely positioned duplicate to avoid intrinsic-width oscillation, and pauses off-screen animations via `IntersectionObserver`; Chimera still uses Motion/JS-loop animation. This is a substantial **behavioral divergence**, not formatting. The component has numerous existing main/legacy consumers; migrate with actual browser resize, scroll, visibility and cleanup tests before replacing it.
- `frontend/ui/src/tooltip.tsx`: reference uses a controlled open state and an app-level TooltipProvider with nonzero hover delay; Chimera supplies a zero-delay provider around each tooltip. `TooltipBubble` has been aligned for the shared tooltip implementation, but the remaining root behavior difference requires the app provider and existing consumers to migrate as a separate slice.
- `frontend/ui/src/dropdown-menu.tsx`: ref centralizes popup motion in `MenuSurface`; Chimera still defines a local `MotionContent`. The now-aligned `MenuSurface` makes this a likely next slice, but menu focus, dismissal and keyboard behavior must be tested first.
