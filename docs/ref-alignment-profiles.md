## DIFF-PROFILE-04: hold background Profile producers through core startup

- Objective: prevent scheduled subscription refresh, external-file watchers, and materialization-journal polling from running before core startup reconciliation has completed.
- Explicit non-goals: change Profile persistence or IPC DTOs; delay manual Profile operations; change startup's existing error reporting; create a separate sync owner for the main UI, legacy UI, or agent.
- Reference implementation: `ref` commit `31019da14006b384b3272c72b4088179a9e72c47`. Read `backend/tauri/src/state/profiles/actor.rs` (`ProducerGate`, `pre_start`, `reconcile_committed`, `start_producers`, and guarded producer messages), `backend/tauri/src/client/profiles.rs` (`ProfilesClient::start_producers`), and `backend/tauri/src/utils/resolve.rs` (`startup_reconcile` followed by `start_background_sources`). The source was read directly from that commit object; the checked-out reference worktree was left untouched.
- Chimera mapping: the same actor paths live in `backend/tauri/src/state/profiles/actor.rs`; `ProfilesClient::start_producers` is in `backend/tauri/src/client/profiles.rs`; `ChimeraClient::init_core` awaits `CoreLifecycleClient::startup_reconcile`, which returns a terminal-operation wrapper, and then awaits producer registration. `backend/tauri/src/utils/resolve.rs::resolve_setup` awaits `init_core`. The main subscription card reads scheduler `next_run_at` through `useProfileSyncStatus`, matching the ref's `SubscriptionCard` rather than deriving a deadline from `updated_at + update_interval`.
- Changed interfaces: `ChimeraClient::init_core` becomes async and is awaited by setup; the internal typed client adds an async `start_producers` actor call that returns after the actor completes its best-effort registration attempt for scheduled jobs and external watchers. No public IPC, generated binding, persisted-data, or agent tool contract changes. Main and legacy UI operations continue to use the same Profile client; the agent continues to use the shared application API.
- Difference and reason: startup releases producers after a terminal lifecycle response, including a completed reconciliation whose inner result is an error, matching ref's behavior after its startup workflow returns. The release call waits for the actor to finish registering background producers; a fire-and-forget cast allowed the app or tests to advance time/change an external file before the scheduler or watcher was actually ready. Manual refresh/import remain available while held. Scheduled refresh messages, external-file events, and journal reconciliation messages are ignored until release. This closes the previous race where `post_start` began background work while `resolve_setup` only queued startup reconciliation. If the lifecycle client fails before returning a terminal reply, startup logs that Profile background producers remain held; the app must restart after the lifecycle actor recovers. This preserves the gate when the operation outcome is unknown instead of launching background work against a possibly unreconciled core.
- Risk and rollback: L2, because this changes core startup ordering and Profile scheduling/runtime coordination. Roll back the producer-gate changes in the Profiles actor/client and restore the previous `init_core` startup enqueue; this also restores the former immediate post-start producer behavior.
- Required approval: L2. The maintainer explicitly approved submitting and pushing the Profile-sync batch after independent review. Merge remains gated by current required checks and review.
- Verification: `cargo +nightly test --manifest-path backend/Cargo.toml --locked -p chimera startup_reconcile -- --nocapture` passed 2/2; `cargo +nightly test --manifest-path backend/Cargo.toml --locked -p chimera client::profiles::tests:: -- --test-threads=4` passed 72/72 after changing producer startup to await actor registration. The suite covers scheduled startup/catch-up and held external-file events, and now completes reliably without racing the asynchronous release message. `cargo clippy --manifest-path ./backend/Cargo.toml --all-targets --all-features`, package-scoped rustfmt, and `git diff --check` passed; Clippy reports existing warnings. Desktop startup/UI E2E has not yet run for this follow-up.
- Convergence condition: keep producer startup tied to the terminal reply from `CoreLifecycleClient::startup_reconcile`. If `resolve_setup` becomes asynchronous, move the await there without changing the gate semantics; retain a startup-ordering regression in the Profile actor suite.
