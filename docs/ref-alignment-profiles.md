- Difference and reason: Chimera retains its `CoreLifecycleClient` and `CoreFacade` boundary for local and Chimera Service execution. Profile mutations now pass through a dedicated `ApplicationWorkflowClient` actor using ref's participant → workflow → TCC shape. `MutationRequest` carries an additional completion channel so the source participant can wait for Confirm/Cancel, including after its prepare waiter times out. Profile operations use ref's `OperationId` identity. A typed, known-not-admitted `QueueFull` result may be deferred for `Save` commands and schedules a rebuild after source commit; other runtime failures fail the Profile transaction closed. Rollback restores the prior Profile snapshot; failed restore, unresolved source decision, or an unsettled source-resource abort latches `RecoveryRequired`, which is surfaced in the mutation receipt. Test coverage exercises commit, source abort/compensation, safe deferral, failed compensation, and an abandoned prepare waiter. This is still a bounded Profile migration slice rather than the full ref workflow: the actor serializes Profile mutations only, while core lifecycle commands remain on the separate `CoreLifecycleClient` actor; the remaining recovery record is a latch rather than ref's typed `MutationReceipt`/`RecoveryContext`; application and clash writers have not yet joined this participant. These differences are tracked convergence work, not permanent product exceptions. Chimera's generated IPC file exposes direct `commands` but does not generate ref's `queries`/`mutations` descriptors, so `profile-bindings.ts` exports the corresponding typed Profile descriptors without editing generated output. Its `RemoteProfileImportMode::Direct` and global-transform mutations remain explicit Chimera extensions. In the transform path, `JSRunner` now uses ref's OXC `FunctionVisitor`/`wrap_script_if_not_esm` strategy and accepts both supported script forms; it keeps QuickJS for execution and enforces Chimera's memory budget through a capped allocator because `Runtime::set_memory_limit` is a no-op with a custom allocator. Parsing the original, untrimmed source also avoids the span offset error that would result from inserting into a source with leading whitespace. These engine and memory-isolation choices are Chimera runtime adapters, not a change to Profile's public transform contract.
